# Contract Studio 领域术语

这些术语用于讨论功能图、节点属性以及需求与实现之间的关系。

## Language

**功能**：
用户能够使用、观察结果并判断是否满足需求的一项能力。
_Avoid_: 用一个文件或一个函数直接代称整个功能

**功能节点**：
功能图中表达一项功能或有业务意义的处理步骤的单元，可以由多个函数共同实现。
_Avoid_: 未说明含义的“代码块”

**节点属性**：
描述节点职责、输入、处理规则、输出、异常和验收条件的信息。
_Avoid_: 将属性统称为“备注”

**节点契约**：
一个节点接受什么输入、遵循什么规则、提供什么输出，以及如何判断行为正确的约定。
_Avoid_: 将标题和描述当作完整契约

**节点描述文档**：
集中呈现一个节点的职责、行为及关联需求、实现和测试的可读说明。
_Avoid_: 与当前节点无关的独立说明副本

**实现关联**：
功能节点与承担其行为的实际代码之间的对应关系。
_Avoid_: 将代码位置的关联称为“实现完成”

**验收证据**：
用于判断功能是否满足验收条件的实际运行记录或检查结果。
_Avoid_: 将测试文件的存在称为“测试通过”

**需求条目（Need）**：
具有稳定身份、明确内容并可与其他条目建立关系的工程记录；需求、功能规格和测试规格是不同类型的条目。
_Avoid_: 将所有条目都称为“用户需求”

**需求索引**：
从需求条目及其关联内容生成、供查询和追踪使用的结构化视图。
_Avoid_: 将索引副本称为“需求原文”

**前后端功能对应**：
同一项用户能力在界面操作、后端行为和验收证据之间的对应关系。
_Avoid_: 要求每个内部函数各有一个界面控件

**运行能力**：
项目已经接入、可以实际调用的一项功能及其操作约定。
_Avoid_: 将刚画出的节点称为“可运行功能”
