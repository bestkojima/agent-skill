# 验收 Skill 的可复用开发流程

## 验收对象

验收 `.agents/skills/contract-studio/SKILL.md` 及其必要参考资料能否指导 AI 完成真实开发任务。工作台是支持工具，计算器、平均值和反馈工单是演示与测试题；示例功能正确只证明该题的实现正确。

## 独立使用试验

给一个未参与本轮设计、使用新上下文的 AI：当前 Skill、一个隔离的非计算器小项目，以及具体业务需求。提供现有项目和保留行为所需的原始材料，不提供预定方案、答案或本轮实现记录。

让它按 Skill 自行理解项目、确定节点契约、划分函数、接通前后端并验证。保留产物和实际运行证据，再由验收者对照原始需求检查。试验工程留在隔离工作区，不加入正式示例目录。

## 判断标准

1. **按功能理解需求**：节点代表用户能力或有意义的处理步骤，输入、输出、规则、异常和验收条件明确；确认状态与实际授权一致。选定契约及开发上下文在业务代码修改前保存。
2. **适应现有项目**：沿用项目有效的入口、数据含义和工具，不机械复制计算器目录、命令或运行模型。
3. **函数职责清晰**：区分校验、纯业务逻辑、流程组织和展示，共享逻辑有实际用途；旧调用方的约束仍成立。
4. **前后端真实对应**：用户能从前端完成新操作，成功结果和错误来自实际后端；实现引用能定位到代码。
5. **证据可核对**：测试覆盖需求中的关键行为、错误路径与既有行为；需求／代码／测试关联使用实际来源，明确区分源码引用、运行记录和测试报告。
6. **交付结论准确**：报告可用入口、已验证行为和剩余缺口，不将缺失的交互验证或未执行的工具说成通过。

试验结果按上述标准逐项写明观察到的产物与行为。发现偏差后，定位为 Skill 指引缺口、执行失误或环境限制，再做针对性修正。一次试验结论只覆盖该任务及实际观察到的行为。

## 独立试用：单个跨项目场景行为通过

2026-11-13，独立 AI 在隔离的原生 Node.js 订单项目完成优惠功能，沿用原 HTTP 服务、HTML 界面和测试工具。验收者已检查实际契约、代码、运行报告和试用总结。

- **需求与节点产物**：2 条需求、3 个功能节点，包含输入输出、异常、关联和前后端定位；可读合同与开发上下文从同一源生成。
- **功能及兼容性**：原价 100、减免 20% 显示 80；0%／100%、空值和越界场景得到验证。原 `subtotal` API 与界面保留，旧操作无需新增比例输入。
- **实际执行**：11 项自动测试、7 个浏览器场景通过。
- **真实索引**：Sphinx-Needs 与 CodeLinks 构建并被消费，包含 2 条需求、5 个 needs 对象、7 处源码引用，未知 ID 为 0。HTML 内嵌脚本明确列为未索引，保留手工前端定位；ubCode 未连接。
- **执行偏差**：执行者编码前在分析中确定了契约，但契约与接手文档落盘晚于业务代码。产物完整，契约先行的执行顺序未通过。

证据保留于隔离目录 `C:/Users/LG/AppData/Local/Temp/contract-skill-transfer-20261113-211814/`：`docs/SKILL_TRIAL.md`、`evidence/run.json`、`evidence/node-test.txt`、`evidence/browser-results.json`、`evidence/sphinx-build.txt` 和 `evidence/index-consumption.txt`。该目录用于本次试验，不纳入产品示例。

本次证明 Skill 能在一个非计算器项目中指导功能划分、前后端贯通、兼容性保留和真实证据交付。手机视口、网络中断未验证；跨语言及更复杂项目的普遍可靠性仍没有本次证据。

### 根据试用修正的指引

1. **工作台检查按项目适用**：仅在项目已有工作台或任务要求建设工作台时检查图展开、节点编辑等交互，其他项目沿用自己的界面。
2. **契约先保存**：明确选定节点契约和开发上下文在业务修改前保存，不给已授权工作增加逐步审批。
3. **外部项目有可复制入口**：新增[外部项目起步指南](../.agents/skills/contract-studio/references/external-project.md)，先映射已有源，再按缺口提供最小 RST、实际 Sphinx／CodeLinks 配置、Windows 构建包装、索引消费及未覆盖语言报告。业务 API 和金额规则留给各项目决定。

### 起步指南的定向复验通过

独立执行者在上述隔离目录的 `guide-check/` 按指南落地 RST、Sphinx／CodeLinks 配置及构建、消费脚本，复用已安装环境。实际构建与消费得到 2 个 needs 对象、2 处源码引用，未知 ID 为 0；需求的 `draft` 状态、节点到需求的 `links` 均保留，源码准确定位至 `server/price.mjs:1` 和 `tests/price.test.mjs:3`。实际存在的 `public/index.html` 同时保留显式节点引用与 `unindexed` 记录。

首次构建只触发缺少 remote 的警告；执行者按指南核实本地专用仓库事实后，仅精确处理 `codelinks.git_remote`，保留其他警告的 `-W` 失败规则。随后构建与索引检查均退出 0。证据见 `guide-check/RESULT.md`、`guide-check/evidence/build-final.txt`、`guide-check/evidence/index-check.txt` 和 `guide-check/docs/normalized-index.json`。

本次定向复验覆盖单个 Node.js 项目的起步链，没有重复安装依赖、重做业务测试或浏览器验收，也未验证多源码项目别名及其他语言。契约先行的保存顺序尚未重新观察；独立业务试用的结论仍限于前述单个跨项目场景。
