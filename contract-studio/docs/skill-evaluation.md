# 验收 Agent 对框架的使用

验收 Skill 能否让 Agent 使用 Contract Studio 的既有能力完成节点任务。框架负责数据、操作入口与约束，Skill 负责引导；计算器等业务只用来承载示例。

## 四个观察点

1. **读对上下文**：从当前图、需求和索引定位节点及直接依赖，区分直接函数与相关函数、内部输入与试运行输入，识别未保存草稿、过期任务和未绑定能力。
2. **用同一份契约**：沿用框架字段与保存入口，在实现前保存节点契约和任务上下文，修改其拥有的 JSON 或原生 RST，保留需求 ID 与实际确认范围。
3. **靠规范生成关联**：按授权实现业务与测试，在函数标记精确 spec ID、在原生测试声明中填写 `verifies`。重建后自动出现节点、属性和具体函数；需要执行时才接入可信能力及测试文件。新增节点应无需修改追踪核心或手写对应表。
4. **留下真实证据**：按 Skill 使用 Sphinx-Needs / CodeLinks 构建入口，读取或按授权运行测试；以真实文件与稳定测试 ID 核对验收结果，分别报告需求确认、索引状态和实际结果。

## 怎么观察

给独立 Agent 当前 Skill、可用框架和一个节点任务，观察它是否沿用上述入口完成工作。对照保存后的节点、实际绑定和执行记录判断偏差，区分指引缺口与框架缺口。需要修复框架的能力由实现承担，避免不断向 Skill 填入补丁式教程。

以框架中的节点任务为验证单位，业务计算正确性另由对应示例测试负责。
