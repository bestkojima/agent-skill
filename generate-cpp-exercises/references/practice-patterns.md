# 实践模式与领域要点

只读取与当前目标有关的部分。下面是帮助选题和补齐题设的要点，不是必须全部实现的功能清单。

## 选题：从能力到证据

| 学习目标 | 可讨论的小 demo | 必须观察到的行为 |
|---|---|---|
| 理解调度如何分配 CPU | 进程调度演示器；策略对比实验 | 任务被选中、执行、让出 CPU、保留进度并继续执行 |
| 掌握进程通信 | 父子进程消息交换；任务与计算结果传递 | 数据实际跨进程传递，通信结束后资源被回收 |
| 理解线程协作 | 共享账户；任务生产与消费 | 共享状态满足不变量，等待与唤醒有明确条件 |
| 掌握 TCP 应用通信 | 请求响应客户端与服务器 | 连接建立、消息收发、协议解析及退出 |
| 理解消息边界 | 分块数据驱动的解码器；真实收发中的解码 | 不完整消息等待后续数据，完整消息被依次还原 |
| 理解 RAII | 管理文件或受控资源的包装器 | 正常与异常退出时释放资源，所有权转移有明确规则 |
| 理解页面置换 | 页面访问演示程序；策略对比实验 | 访问引起命中、缺页与替换，驻留页面状态真实变化 |

优先选能让学生动手完成且观察清楚的场景。若用户已经确定方向，直接设计该场景，不重新展示整张候选表。

## 进程调度与教学模拟

调度 demo 的中心是任务推进、调度选择、进度保留和状态切换。以程序中保存的状态与任务结果驱动日志；不可只输出预先准备的时间线。

在模型中明确：

- 模拟 CPU 数量、时间单位、可见状态、每次执行如何推进任务，以及模拟的结束条件。
- 进程何时进入就绪状态，是启动时全部就绪，还是带到达时间。选择哪一种服务于本题目标，不必同时支持。
- 调度策略、同时到达或同优先级的顺序；若有时间片，明确提前完成与时间片耗尽的处理。
- 若允许执行中到达，明确时间片结束时新到达与当前进程重新入队的先后；若就绪集合为空，明确空闲处理。
- 是否包含 I/O 阻塞和切换耗时；只实现与当前目标有关的机制。

模拟进程再次获得 CPU 时应继续推进自己的任务，已完成的进程退出。基础题可以用分步累加、分批处理元素等受控任务表示执行，不必要求类继承、真实线程或内核接口。

验收可检查每一步恰好执行一次、结果与完整执行一致、状态转换符合规则、只剩一个任务时仍可完成。等待与周转指标只有在教学目标需要时加入，定义需与模型一致。

日志是教学模拟的观察手段，不代表操作系统真的发生了对应进程切换。页面置换等模拟同样要让内部状态随事件真实更新，并注明与真实硬件或内核的区别。

## 真实进程与管道

用户要真实进程通信时，保留系统接口实践，并明确平台。双向通信要有明确的两个方向及协议，可使用两条管道等合适方式；不要把一个普通单向管道写成通用全双工连接。

题面需交代由谁创建进程、双方发送什么、如何识别消息完成、何时关闭各端、如何回收子进程。处理可能的部分读写，阻塞操作要有可理解的退出路径。

对于入门 demo，可以只做一次有限大小的请求与响应，不叠加并发请求、重试和完整 RPC。需要复现时，用实际数据交换和退出状态验收，不要求父子进程日志总是交错成同一顺序。

## 互斥锁、条件变量与线程协作

以共享状态的不变量和工作完成情况验收，例如余额符合操作总和、任务不丢失不重复、容量不越界、线程能够结束。

- 明确共享数据、任务数量或停止信号，以及线程退出和等待回收规则。
- 条件变量练习必须有受同步保护的条件状态，不能把通知当作能自动记住所有历史事件的消息队列。
- 固定输出顺序若是目标，应要求通过显式同步建立顺序。不要依赖 sleep、线程启动先后或一次偶然结果。
- 不要求通过执行存在数据竞争的 C++ 程序，稳定得到某个“错误值”；需要对比时可讨论错误设计的原因。
- 压力运行可以帮助发现问题，但不能单凭“多次没有出错”认定并发代码正确，仍须检查同步关系和不变量。

降低难度可以固定生产者或消费者数量、提供任务数据与启动外围代码，保留等待、唤醒或互斥这个主要学习动作。

## TCP 与消息边界

先辨别目标是“会使用 Socket”还是“理解字节流的应用层消息解析”。学生还不会 Socket 时，可讨论用分批传入的数据驱动解析器，明确它是应用层模拟；已经指定真实通信时保留真实连接。

- 定义应用消息格式：边界、长度字段含义、编码或字节序、长度限制，以及需要处理的非法或不完整数据。
- 一次读取不等于一条应用消息。真实收发需考虑部分读写，不能保证一次发送对应一次接收。
- 固定切分的字节块可稳定演示半个头部、部分正文和多条消息连续到达。真实网络 demo 不强求某次分包现象必然出现。
- 明确空消息、对端关闭和剩余不完整消息是否在本题范围内，以及程序如何结束。

验收聚焦重组内容、顺序、完整性和协议处理。连接管理、超时与重试按学习目标加入，避免一个消息解析练习扩展成完整服务器框架。

## C++ 语言机制与资源管理

把语法知识转成运行行为：RAII 对应作用域与异常路径中的资源释放；移动语义对应所有权转移；智能指针对应具体生命周期关系。

- 明确谁拥有资源，是否允许复制或移动，以及空状态、释放和转移后的行为。
- 用受控计数或实际资源行为观察泄漏与重复释放，不把内存地址当作固定期望输出。
- 目标是实现包装器时，让学生完成核心资源管理；目标是正确使用标准库智能指针时，使用标准库即是任务的一部分。
- 需要稳定日志时考虑标准版本和复制消除，不把所有构造与移动次数都当作固定值。
- 不要求推算未定义行为的确定输出；诊断练习应识别原因并修正设计。
